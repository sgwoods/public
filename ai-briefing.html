Release notes

v0.1.5-beta · 2026-10-22

  • Fix: the scheduled jobs had been firing exactly one hour early every day (the 05:00 run started at 04:00, the 20:30 preflight at 19:30). launchd now only ticks every half hour, and the Mac's own local clock decides when a scheduled time has come (pipeline/schedule.py, ./np scheduled). Times must be on :00 or :30.
  • Releases refuse checkout-local files (.venv, .env, .staging) committed on dev; .venv is ignored as a link too.
  • Fix: rebuilding an edition (./np rebrief, ./np staging run) failed with KeyError 'critique', because the evidence check on Must reads needs the critique model, and a rebuild had stopped loading it. Found by the first staging run.
  • Git safety: every git call in the export, hub, dev and release code ignores GIT_DIR / GIT_WORK_TREE from the environment, and the tests that build throwaway repositories clear them. A leaked GIT_DIR once pointed a test's git init at the production repository and wrote a wrong core.worktree into its config. Caught and fixed before any run used it.
  • The first release built on dev and promoted with ./np release.

v0.1.4-beta · 2026-10-22

  • Development checkout: ./np dev setup creates a second working copy of the repository on branch dev, in staging mode. Inside it: - ./np staging sync brings in production's latest data and fixes; - ./np staging run [DAY] rebuilds an edition with the development code while outbound stays off, and --email sends the review copy to the owner only; - ./np staging reset throws away what staging wrote.
  • Staging outputs can't be committed: the pre-commit hook refuses data paths in a staging checkout, archive commits are skipped there, alerts aren't sent, and services can't be installed. Staging runs keep out of the 03:30–08:30 production window.
  • Releases and rollback: - ./np release VERSION "reviewed: ..." merges dev into production between 08:30 and 20:00, needs one approval, then tags the release and pushes the public code, the backup and the hub status. It refuses if production has stray code changes, a run is in progress, dev's version or changelog don't match, or the staging marker was committed. - ./np rollback "reviewed: ..." returns the code to the previous release.

How it is made

Curated sources

Lab and company posts, trade press, researchers and newsletters, every feed verified live before it is used.

Evidence first

Each story is weighed by what kind of source backs it; every Must read gets an evidence check, and figures that trace to no source are looked up or cut before anything is sent.

Local first

Runs each morning with local models for most stages and Claude for the critical pass and editing; voiced locally.

Release gate

Nothing goes out (site, podcast, email) unless tests, a secrets scan, privacy checks and a human approval of sensitive changes have passed. Changes reach production as releases.

Current focus

Beta: aggressive fact checking before email and audio, wider source coverage; podcast listing after four green weeks.
