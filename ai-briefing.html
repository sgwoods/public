Release notes

v0.1.7-beta · 2026-10-22

  • Shipped editions don't break. Once a day's email has gone out, that day is shipped (pipeline/shipped.py), and:
  • Publish guard: before every production publish, the new site is checked against what readers already have. It refuses (the live site is untouched and the owner is emailed) if any of these hold: - a shipped day page or deep dive is missing; - a shipped edition's text changed without a correction; - a shipped MP3 inside the retention window is missing; - the home page or a feed is missing, or the podcast feed would shrink.
  • Corrections are explicit: rebuilding a shipped day (rebrief, reprocess, remaster) needs --correct "what changed", and the page shows "Corrected <date>: …".
  • Remasters keep the old audio: the earlier MP3 is carried over from the live site, so no audio URL breaks.
  • After-publish check: once the site is live, the newest shipped pages, both feeds and the latest MP3 must answer. If not, the previous site is put back automatically, the email is held, and the owner is emailed. ./np publish restore does the same by hand.
  • The email waits for a good publish: if the publish fails or the after-publish check fails, no subscriber email goes out. Before, it went anyway.
  • Audio retention: 30 days on the site and in the podcast feed, up from 14. 60 days would be about 1 GB, the GitHub Pages limit.
  • Slack: links any member posts in the team channel now count, links only. Who posted is never stored, and their text is never used.
  • Staging preview: carries only the newest day's audio. The first full preview push timed out.
  • Site pushes are sturdier: a push that stalls (under 1 KB/s for 60 s) fails and is retried once over HTTP/1.1, instead of hanging the morning run. Pushes no longer use one huge buffered upload, which is what GitHub was timing out with HTTP 408.

v0.1.6-beta · 2026-10-22

  • Development preview: ./np staging publish [setup] publishes the dev checkout's site to its own Pages repo (sgwoods/ai-briefing-staging). The preview has a banner on every page linking back to the published site, is kept out of search engines (noindex, robots.txt), and has no subscribe form and no podcast feed. Staging can publish only there, and production never publishes there.
  • ./np staging compare [DAY]: staging against production for the same day: sections, counts, words, source links, the evidence mix, fact-check counts and audio length, plus the privacy scan of the preview and a diff of the edition. Writes logs/compare-DAY.md and flags what needs review.
  • Fix: a staging run no longer copies its MP3 into the owner's iCloud folder. The first staging run had overwritten that day's copy. It no longer deletes iCloud files either.
  • Tests always run as production (NP_ENV=production), in either checkout.

How it is made

Curated sources

Lab and company posts, trade press, researchers and newsletters, every feed verified live before it is used.

Evidence first

Each story is weighed by what kind of source backs it; every Must read gets an evidence check, and figures that trace to no source are looked up or cut before anything is sent.

Local first

Runs each morning with local models for most stages and Claude for the critical pass and editing; voiced locally.

Release gate

Nothing goes out (site, podcast, email) unless tests, a secrets scan, privacy checks and a human approval of sensitive changes have passed. Changes reach production as releases.

Current focus

Beta: aggressive fact checking before email and audio, wider source coverage; podcast listing after four green weeks.
